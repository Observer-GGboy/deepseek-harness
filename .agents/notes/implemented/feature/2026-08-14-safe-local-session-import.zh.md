# Agent Note: 安全导入本地 Session

Status: implemented

[English](2026-08-14-safe-local-session-import.md) | 中文

## 问题

Codex 与 Claude Code 用户可能拥有早于 DeepSeek Harness 的有用本地对话历史，但这些文件不是 Harness 事件日志。把外部 JSON 当成 `SessionEvent`、把完整文件复制到浏览器，或重放工具状态都会跨越信任边界：供应商格式包含隐藏指令、推理、凭据、路径、附件、命令和部分写入的流记录。重试或并发导入还可能创建重复 Session，或暴露只发布了一部分的事件日志。

用户仍然需要一个明确的继续点：选择一个来源、检查安全事实、选择约束未来工作的 Workspace、Agent 预设与精确模型路由，并在不恢复外部进程的情况下开始普通新轮次。

## 决策

本地导入是一条由五个包组成的能力 seam。`dsh-session-import` 定义提供方注册表与中立快照；Codex 与 Claude Code Service Provider 归约受支持的供应商记录；`dsh-session-import-local` 负责不透明预留、原生转换、确定性持久化与 Remote 方法；`dsh-client-ui-session-import` 负责 Settings 确认流程。

发现阶段只读取元数据。捕获固定初始 JSONL 字节前缀，并在配置的来源、单行、可见字节、可见消息和工具数量预算内流式处理完整记录。它会对同一前缀执行两次哈希，并比较文件身份与大小。追加内容可以继续写入，但位于捕获前缀之外；替换、截断、中段变更、格式错误的完整记录、格式漂移、冲突重复和时间戳乱序都会故障关闭。末尾不完整记录会被忽略并报告。

外部记录绝不实现或反序列化为 `SessionEvent`。提供方输出不可变的 `ForeignSessionSnapshot`，其中只包含可见且已脱敏的用户／助手文本、带标记的生成摘要、不可执行的工具名称／状态、安全来源信息、计数和可选 cwd 提示。系统／开发者指令、推理、工具参数／结果、附件、环境值、凭据和来源路径没有中立字段。Host 消费方会在转换前再次校验并脱敏快照。

转换器 v1 使用显式外部版本策略，而不接受任意未来记录。Codex 接受 `0.144.0` 至 `0.148.999`（包括数字核心在范围内的预发布版），允许重复且一致的 `session_meta`，并记录所有观察到的受支持版本。Claude Code 接受 `2.1.128` 至 `2.1.222`，把受支持的更新器过渡记录为最小／最大范围，并显式把在 2.1.128 中观察到的不含正文 `frame-link` 记录视为忽略的元数据。缺失、格式错误、过旧、更新、身份冲突或未知必要结构都会故障关闭。

## 身份与发布

目标 Session id 对领域分隔符、Host 本地来源文件身份与来源 Session 身份、捕获前缀 SHA-256 摘要执行哈希。捕获时间不影响身份，因此等价捕获会收敛。Host 本地文件身份永远不会持久化、记录日志或返回 Client。

用户显式确认现有 Workspace、可用 Agent 预设与精确 provider/model 路由。Workspace 与预设成为不可变的 `SessionHeader` 值，路由及其组装后的预设内容成为原生请求状态。使用不同选择复用同一个确定性目标会产生可见冲突，而不是改写元数据。

消费方构造完整、平衡的原生 seed，并通过 `SessionStore.prepare()` 校验。首次持久化追加包含 `session/imported`、所有已关闭的导入轮次、`session/end-seed` 与已确认的继续请求状态。JSONL 使用禁止替换的首次实体化；SQLite 在同一事务中写入 header 与事件批。该首次完整批同时是认领点与发布点，因此不存在持久的仅预留或部分发布 Session。认领失败后，有界且可取消的检查窗口会等待独立获胜方的原子发布变得可见。包括独立进程在内的等价失败方随后返回同一个 id。

Workspace 关联刻意在发布后尽力执行。关联失败会返回 `workspaceAttached: false`；完整 Session 仍可选择、可使用。重试会检查现有导入，不会再次追加 seed。

## 继续与信任

导入的工具历史会变成一条带显式标签、不可执行的用户上下文摘要。系统不会合成原生工具调用或结果事件，因此没有历史命令能够执行。导入的可见消息会成为已关闭的原生轮次。发布前，消费方会在脱离持久化的 Session 上组装所选预设的系统提示词和工具，把确认的 provider/model 存入 `request/header`，并计量最终 seed。安全容量为所选上下文窗口减去模型默认输出额度（缺失时取 10%），再减去 4096 token 与窗口 10% 中较大的组装及下一提示词预留。只有用户在已确认的 Workspace、预设与路由下发送下一条消息后，新的代码、工具、审批和模型工作才会开始。

Web Client 只接收来源元数据、捕获计数、cwd 提示、安全的逐模型额度与不透明预留 id。它绝不接收 transcript 摘录或文件路径。离开分节会丢弃未提交的预留；捕获与提交都接受取消。等待同一提交的多个调用方可独立取消，只有最后一次取消才会中止共享工作。预留是有界且进程本地的，而已提交的幂等性跨标签页、进程、重启、JSONL 与 SQLite 持久成立。v1 进度约定只报告发现／捕获／提交阶段；在没有真实 Remote 进度 seam 时，不暴露字节计数。

## 验证

提供方 fixture 固定了仅元数据发现、排除符号链接、稳定追加行为、确定性的读取／重哈希／最终 stat 变更故障、部分尾记录处理、外部版本范围、Codex 重复元数据、Claude Code 2.1.128 `frame-link`、结构性排除、凭据脱敏，以及不含路径／正文的失败。Host 测试让提供方中立快照通过原生 seed 校验，并覆盖逐模型组装计量、持久化／关联故障注入、取消与重试，以及真实 JSONL 与 SQLite 后端上的 2、10 和 100 路竞争；另有六个独立 Node 进程在每种后端上竞争。Client 测试固定三项显式确认、阶段状态、取消、仅元数据渲染和发布后记账警告。四个聚焦的 provider／Host／Client 套件保持 statements、branches、functions 与 lines 全部 100%。一个不使用密钥的真实 Loader + Web + Chromium 场景导入含历史 shell 调用绊线的 Codex 快照，通过 replay 模型继续，验证没有合成或执行 `tool/call`，并提交对应无障碍 golden。

## 考虑过的替代方案

**把外部 JSON 直接导入为原生事件。** 未采用，因为供应商记录不满足 Harness 的顺序、平衡、来源与信任约定，未来格式漂移还会静默扩大原生事件联合。

**复制完整 transcript，在渲染或提示词阶段过滤。** 未采用，因为秘密和隐藏记录届时已经跨越持久化与 Client 边界。系统改为在预留前完成结构性排除与脱敏。

**先持久化预留，再增量填充 Session。** 未采用，因为崩溃与并发读取方可能观察到空白或部分 Session。一个完整、后端原子的首次追加提供单一发布点。

**把 Workspace 与预设纳入确定性 id。** 未采用，因为一份捕获的历史前缀应只有一个持久身份。不同继续元数据会产生显式冲突，迫使用户确认不可变选择。

**恢复供应商进程与工具状态。** 未采用，因为无法从 transcript 安全重建进程、分支、sandbox、权限、hook 和工具状态。导入刻意只保留历史上下文。

## 后果

用户可以继续有用的可见历史，而无需复制或重放外部执行环境。等价重试会在两个随附持久化后端上收敛为一个完整 Session，UI 也可以保持只接触元数据。

代价是刻意丢失：隐藏推理、附件、工具正文、sidechain、供应商运行时状态和捕获后的任意追加都不可用。常见凭据形状会被脱敏，但无法证明不受约束的自然语言中没有秘密；结构性排除与狭窄约定仍是主要边界。新的供应商必要记录结构必须经过审查并显式添加，而不能乐观接受。
